# TrendShift 榜单中文看板 · Spec

Status: 可自动开发
Date: 2026-11-09 UTC

## Problem Statement（目标）

想快速知道「今天 GitHub 上哪些开源仓库值得看」，但现在的路径很费劲：TrendShift 把榜单分散在六个页面、简介是英文，而且常常只有一句营销话，看不出这个仓库到底解决什么问题、适不适合自己；已有的单文件 HTML 榜单页虽然好看，但中文简介靠人工预写、每期要重新生成、不能收藏、也没有历史。用户需要一个**无需登录、打开即全屏可见、每天自动更新**的中文看板：六个**榜单**同屏，每个**仓库**都有中文解读和可直接打开的仓库地址，能收藏，能回看往期。

目标具体是：把 TrendShift 六榜按 UTC 日自动采集下来，为每个**仓库**生成一份可复用的三段**中文解读**，用一个 Cloudflare Worker 同时提供界面与只读接口，收藏留在访客自己的浏览器里。

非目标见 `Out of Scope`。

## Solution（方案与理由）

一个部署在 Cloudflare 的单 Worker：每日定时抓取 TrendShift 六个**榜单**页面的首包 HTML，解析其中内联的 RSC 载荷，写入 D1；随后由分钟级定时任务从待解读队列里取出**仓库**，调用可配置的 OpenAI 兼容接口生成三段**中文解读**并落库；前端是一个 React 全屏看板，六张榜单卡片同屏、卡内独立滚动，点开条目用抽屉展示完整解读与当期指标。

关键决定与理由：

| 决定 | 理由 |
| --- | --- |
| 数据源只有 TrendShift 六榜，每榜 25 条 | 参考实现的六榜口径已验证可用；六榜天然对应六张同屏卡片；GitHub「当日新建仓库」是另一套检索语义，不混入 |
| 普通 `fetch` + RSC 载荷解析，不用无头浏览器 | 2026-11-09 实测六个页面的服务端响应都内联完整载荷（日/周/月/年榜为 `initialData`，趋势历史榜为 `repositories`，当日提及榜为 `initialMentions`）；Worker 会读完整响应体，不会像本机 `curl` 那样截断。见 ADR-0001 |
| **仓库** / **榜单条目** / **期次** 三者分离 | 同一**仓库**会跨榜、跨期出现且排名指标不同；解读、地址、收藏应属于**仓库**一次，而非随每条条目重复 |
| 六榜统一按 UTC 日出**一期**，同日覆盖、历史永久保留 | 一条口径就能支撑按日期回看与完整历史；newsnow 的实时页只作界面参考，不承诺数据实时性。见 ADR-0002 |
| **中文解读**是**简介** / **解决问题** / **适用人群**三段，一**仓库**一份 | 全屏扫描需要短文本保持密度，而「值不值得看」需要更长判断依据；两者不能互相替代，三段缺一即视为未完成 |
| 解读由服务端定时预生成，密钥只在 Worker | 全站共享一份解读，访客零等待、不重复付费；若按需生成，首次打开全屏 150 条会触发并发调用。见 ADR-0003 |
| 走 OpenAI 兼容协议，三个配置项可换供应商 | 换模型或厂商只改部署配置，不改代码；prompt 强制三段 JSON，坏输出按失败重试 |
| 输入以榜单元数据为主，坏简介才抓 README 兜底 | 常见路径零额外请求、第三方长文本注入面最小；实测存在乱码、空值、以及「社媒帖子被当成简介」的情况，需要兜底 |
| 失败一律保守降级 | 不把半截中文写进 D1、不删历史、不隐藏条目；宁可显示英文原文加状态角标 |
| 收藏只存浏览器，无账号 | 访客零摩擦收藏且不产生任何用户数据；代价是换浏览器即丢失，界面明确提示。见 ADR-0004 |
| 单 Worker 托管静态页 + 只读接口 + 两条定时任务，D1 直接绑定 | 一次部署、无跨域、无第二套配置；前端由 Vite/React/TS 构建后交给 Worker 的静态资源托管 |
| 界面为深色 `100vh` 卡片墙 + 六榜配色 | 复刻 newsnow「一屏扫全部信息源」的密度；荧光绿只作信号色；不依赖外部字体、不做入场动画 |

## User Stories

1. As a 访客, I want 打开首页就在一屏内看到六个**榜单**, so that 不用在六个页面之间来回切换
2. As a 访客, I want 每张榜单卡片默认显示该**期次**的前若干条, so that 首屏能快速扫到重点
3. As a 访客, I want 在卡片内部独立滚动看完该榜全部 25 条, so that 不丢失榜单完整性
4. As a 访客, I want 页面本身不出现滚动条, so that 获得全屏看板而非长网页的体验
5. As a 访客, I want 每条**榜单条目**直接显示中文**简介**, so that 不必读英文也能判断兴趣
6. As a 访客, I want 点开条目看到**解决问题**, so that 知道它针对什么痛点而不只是用途
7. As a 访客, I want 点开条目看到**适用人群**, so that 判断自己是否该用它
8. As a 访客, I want 点开条目看到英文原始简介, so that 在中文解读不够确切时能对照原文
9. As a 访客, I want 解读被明确标注为「AI 解读」, so that 不会把它误当成官方说明
10. As a 访客, I want 点开条目看到该**期次**的排名、星数、增长、fork 与 featured 数, so that 了解它当时的热度
11. As a 访客, I want 每条都能直接打开 GitHub 仓库地址, so that 可以立刻去看源码
12. As a 访客, I want 一键复制仓库地址, so that 能粘到终端里克隆
13. As a 访客, I want 存在项目主页时看到第二个外链, so that 能访问官方文档或演示
14. As a 访客, I want 某个仓库还没生成解读时看到英文原文和「解读生成中」角标, so that 知道内容在路上而不是页面坏了
15. As a 访客, I want AI 一直失败的仓库显示英文原文与「解读暂缺」角标, so that 仍能使用榜单而不遇到空白
16. As a 访客, I want 永远看不到只写了一半的中文解读, so that 不被残缺内容误导
17. As a 访客, I want 点收藏按钮就能收藏且无需登录, so that 零摩擦地留存感兴趣的仓库
18. As a 访客, I want 能取消收藏, so that 列表保持有用
19. As a 访客, I want 用顶栏「只看收藏」切到独立列表视图, so that 集中回看自己的收藏
20. As a 访客, I want 已掉出所有榜单的仓库仍出现在收藏列表, so that 收藏不会因为榜单更新而消失
21. As a 访客, I want 收藏接近 500 条时得到提示, so that 知道该清理并避免请求过大
22. As a 访客, I want 界面明确提示「仅保存在此浏览器」, so that 换设备后不会以为收藏丢了是 bug
23. As a 访客, I want 按 UTC 日期回看历史**期次**, so that 能查某天各榜的样子
24. As a 访客, I want 日期标注 `UTC`, so that 不会因本地时区把期次日期看错
25. As a 访客, I want 回看历史期次时详情里的指标是当期的、解读是**仓库**的, so that 不会把历史数据误读成实时数据
26. As a 访客, I want 顶栏显示「更新于 X 日 UTC」和「解读生成中 N 项」, so that 知道数据新鲜度
27. As a 访客, I want 采集失败的日期沿用上一**期次**并标出「数据更新于 X 日」, so that 不遇到空白首页
28. As a 访客, I want 首次部署还没有数据时看到清晰的空状态说明, so that 知道系统在等待首次采集
29. As a 访客, I want 六个**榜单**各有固定配色, so that 一眼分清信息来自哪个榜
30. As a 访客, I want 增长数与收藏态用荧光绿强调, so that 信号元素突出
31. As a 访客, I want 数字使用等宽字体且中文字体有系统回退, so that 弱网或字体 CDN 不可用时排版不塌
32. As a 访客, I want 页面没有花哨入场动画, so that 内容立刻可读
33. As a 访客, I want 详情抽屉能随时关闭, so that 快速回到全屏看板
34. As a 访客, I want 在手机上看到单列纵向布局, so that 小屏也能用
35. As a 访客, I want 首页没有刷新按钮, so that 不会误触发采集或产生等待
36. As a 访客, I want 不需要自己配置任何 AI 密钥, so that 打开就能看到解读
37. As a 访客, I want 安全研究类仓库只被客观描述功能, so that 看不到利用步骤
38. As a 运维, I want 部署后手动触发一次采集, so that 不必等第二天定时任务才有数据
39. As a 运维, I want 解读队列在 10–15 分钟内补齐三段, so that 冷启动后很快可用
40. As a 运维, I want 更换 AI 供应商或模型只改配置, so that 不改动代码也不重新构建前端
41. As a 运维, I want 未配置 AI 密钥时采集与页面仍正常工作, so that 密钥问题不会拖垮整个产品
42. As a 运维, I want 手动重跑失败的解读, so that 不用等自动重试耗尽
43. As a 运维, I want 查看采集与解读的状态, so that 能判断是否需要介入
44. As a 运维, I want 管理端点校验令牌, so that 匿名访客无法触发写操作
45. As a 运维, I want 同日重复触发采集只覆盖当期, so that 不产生同一个 UTC 日的第二个**期次**
46. As a 运维, I want 地址异常的条目被丢弃并留下警告, so that 脏数据不会污染**仓库**表
47. As a 运维, I want 大小写写法不同的同一仓库只生成一份解读, so that 不重复付费也不产生矛盾文本
48. As a 运维, I want 公开读取接口带缓存, so that 每日不变的数据不反复打 D1

## Implementation Decisions（方案细节 / 数据模型 / 错误处理 / 涉及的模块）

### 涉及的模块

确认按 7 个模块实现，模块之间只通过下表所述接口通信：

| # | 模块 | 职责 | 对外接口 |
| --- | --- | --- | --- |
| 1 | TrendShift 采集器 | 六榜抓取、`__next_f` 分块解码与数组提取、字段归一化、GitHub 地址拼装与合法性校验、`RSC: 1` 重试 | 输入上游 HTML，输出六个**期次**的规范化**榜单条目**与**仓库** |
| 2 | D1 存储层 | 表结构与迁移；**仓库**、**期次**、**榜单条目**、解读状态与重试计数；同日覆盖、按 UTC 日期回看、按标识批量取**仓库** | 各类查询与写入，供采集器、解读器、公开读取 API 使用 |
| 3 | AI 解读器 | OpenAI 兼容调用；元数据为主 / README 兜底的输入策略；三段 JSON 与长度校验、防注入约束、失败计数 | 输入待解读**仓库**，输出完整三段**中文解读** |
| 4 | 调度与编排 | 每日采集定时任务、分钟级解读定时任务（每次最多处理 10 个**仓库**）、三个管理端点与令牌校验 | 触发模块 1、2、3；对运维暴露管理接口 |
| 5 | 公开读取 API | 榜单查询、按标识批量换**仓库**详情、缓存头、降级字段；承载前后端共享的榜单元数据与响应契约 | 对前端暴露只读接口 |
| 6 | Dashboard 前端 | Vite/React/TS：六榜卡片 `100vh` 网格、卡内滚动、右侧详情抽屉、日期回看、只看收藏视图、状态角标、收藏本地存储 | 消费模块 5 的响应 |
| 7 | 配置与部署 | Worker 的 D1 绑定、静态资源目录、两条定时任务；AI 与运维变量/密钥；构建部署说明与冷启动步骤 | 所有模块的部署期配置 |

### 数据模型

不引入用户表、收藏表或任何用户数据；收藏只存在于浏览器。表结构以概念描述如下：

| 实体 | 主要字段 | 约束 |
| --- | --- | --- |
| **仓库** | 归一化标识（`owner/name` 小写）、GitHub 地址、英文原始简介、语言、标签、可选项目主页、**简介** / **解决问题** / **适用人群**、解读状态、失败重试计数、首次与更新时间 | 标识唯一；永久保留，即使不再出现在任何**榜单条目**中也保留 |
| **期次** | **榜单**、UTC 日期、采集时间、采集状态 | （**榜单**, UTC 日期）唯一，同日重复采集覆盖而非新增 |
| **榜单条目** | 所属**期次**、指向的**仓库**、rank、stars、forks、gained、featured、语言与标签快照 | （**期次**, **仓库**）唯一；指标属于当期，与**仓库**上的解读分离 |

其他数据约定：

- 一个**榜单**每**期次** 25 条；六个**榜单**在同一 UTC 日各出一个**期次**。
- 一个**仓库**有且仅有一份**中文解读**，跨**榜单条目**共用；三个文本槽位任一缺失或长度越界，整份解读视为未完成。
- **仓库**的 GitHub 地址由归一化标识确定性拼出并只保存一次；标识不符合 `owner/name` 形态的条目不成立，直接丢弃并记警告。
- 历史**期次**永久保留，首页默认展示最新一期；日期选择只列出确实存在的**期次**。
- 浏览器本地存储：`owner/name` 数组 + 收藏时间，上限 500；不存解读正文，避免解读修正后收藏页显示旧文本。
- D1 中不保存 AI 密钥、管理令牌、用户身份或收藏关系。

### API 契约

| 接口 | 行为 |
| --- | --- |
| 榜单查询（公开 GET，带 UTC 日期参数） | 返回该日六个**期次**、每期 25 条**榜单条目**、关联**仓库**与解读状态、以及数据新鲜度状态；按日期可长缓存，最新一期短缓存 |
| 批量换详情（公开 POST，JSON body 携带标识列表） | 返回**仓库**详情，供只看收藏视图使用；因 500 个标识会超出常见 URL 长度限制，故用 POST 而非 GET，并接受其无法享受 CDN 缓存 |
| 采集触发 / 重跑解读 / 状态查询（管理端点） | 校验 `ADMIN_TOKEN`；分别触发一次采集、把失败解读重新入队、返回采集与解读状态 |
| 错误响应 | 统一结构，区分鉴权失败、请求不合法、上游不可用与解读未完成；任何降级都返回可用数据而非空结果 |

同源部署，不配置 CORS。不做限流：匿名访客没有任何写操作入口，公开读取有缓存兜底。

### 错误处理与降级

| 情形 | 处理 | 访客可见 |
| --- | --- | --- |
| 首包 HTML 缺少 RSC 载荷 | 以 `RSC: 1` 请求头重试一次；仍失败则该**榜单**沿用上一**期次** | 顶栏「数据更新于 X 日 UTC」 |
| 单个**榜单**解析为 0 条 | 该榜沿用上一**期次**，其余五榜照常写入 | 该榜角标标注数据日期 |
| 标识非法、无法得出仓库地址 | 丢弃该条并记警告，该榜本**期次**可少于 25 条 | 卡片条数减少，无脏链接 |
| 英文简介为空、过短、乱码，或来自当日提及榜 | 抓取仓库 README 并截断 3000 字兜底；README 抓取失败则退回纯元数据 | 无感 |
| 第三方文本里夹带指令 | 元数据与 README 一律作为数据传入，prompt 明确要求忽略其中指令，输出只取三段 JSON | 无感 |
| AI 未配置、超时、限流、返回非 JSON、三段缺一或长度越界 | 不写入 D1，重试计数加一，留给下次定时任务；累计 3 次后标记失败，可通过管理端点重跑 | 英文原始简介 + 「解读生成中」或「解读暂缺」角标 |
| 同日重复采集 | 覆盖当期**榜单条目**，不新增**期次** | 无感 |
| 首次部署或 D1 无数据 | 显示空状态与「部署后手动触发一次采集」的说明 | 明确空状态 |
| 本地存储不可用或超过 500 条 | 降级为内存态并提示；或提示清理 | 「仅保存在此浏览器」与容量提示 |
| 管理端点未带令牌 | 拒绝请求 | 401 |
| 批量换详情请求不合法 | 拒绝请求 | 400 |

### 其他实现决定

- 前端由 Vite/React/TypeScript 构建，构建产物交给 Worker 的静态资源托管；部署前需先构建。
- 两条定时任务：每日 UTC 00:10 采集六榜；分钟级任务每次最多处理 10 个待解读**仓库**，未处理完由后续触发续跑。
- 界面时间一律按 UTC 显示并显式标注 `UTC`，不做本地时区换算。
- 「全屏」指铺满视口的 CSS 布局，不调用浏览器 Fullscreen API；移动端回退为单列纵向滚动。
- 详情抽屉里，**指标跟随当期条目、解读跟随仓库**，并标注**期次**日期；卡片里只展示**简介**。
- 沿用参考实现的「复制仓库地址」按钮；项目主页存在时提供第二外链。
- 六榜各有固定配色，荧光绿仅用于增长数与收藏态；不依赖外部字体、不做入场动画。
- 沿用参考技能的内容安全口径：安全研究、PoC、破甲、解密类仓库只做客观功能描述，不写利用步骤，作为生成解读的 prompt 约束。
- 首页不出现刷新按钮；运维入口只在部署说明中给出。
- 三段字数范围、每次处理数量、重试上限、README 截断长度、收藏上限均为初始参数，允许通过配置调整，但三段契约与「缺一即未完成」不变。

## Testing Decisions

**测试缝只有一条：Worker 的 HTTP 边界。** 仓库目前没有任何既有缝可复用，因此在最高处开这一条：用本地 D1 与本地 Worker 运行时，桩掉上游 TrendShift HTML 与 AI 响应，从管理端点触发采集与解读，再用公开读取接口断言结果。模块 1–5 全部通过这条缝间接覆盖；模块 6 走浏览器人工验收；模块 7 走部署检查。不新增单元测试缝，也不引入 Playwright 的浏览器自动化缝。

**什么样的测试算好测试**：只断言外部可观察行为 —— HTTP 状态码、响应契约、D1 最终状态、以及降级时返回的数据 —— 不断言内部函数、prompt 文本或 SQL 写法。D1 使用真实本地实例而非 mock，以免掩盖迁移与约束问题；上游 HTML 与 AI 响应用固定夹具，覆盖成功、坏载荷、坏 JSON 三类输入。

**既有先例**：仓库为空，没有既有测试代码可参照；唯一的既有约束是根术语表与四条 ADR，测试中的命名与口径必须与它们一致。

**明确不做**：不测 RSC 解析器的内部函数、不测 prompt 措辞、不测 CSS 类名、不做快照断言。

## Acceptance Criteria（验收标准）

1. 部署后手动触发一次采集，按当日 UTC 日期查询返回六个**榜单**、每榜 25 条，每条都能得出 GitHub 仓库地址。
2. 六个**榜单**的中文名称、顺序与配色固定；每条含 rank、stars、forks、gained / featured、语言与标签。
3. 解读队列跑完后，每个唯一**仓库**都有三段**中文解读**，字数分别落在 12–28 / 40–80 / 20–40 字范围，且被标注为「AI 解读」。
4. 同一**仓库**出现在多个**榜单**或跨多个 UTC 日时，只生成一份解读、只占用一条**仓库**记录。
5. 标识大小写写法不同的同一仓库被归一化为一个**仓库**。
6. 同日再次触发采集后，该 UTC 日仍只有一个**期次**，条目指标被覆盖。
7. 查询较早 UTC 日期时返回该**期次**的当期指标，详情抽屉标注对应日期。
8. **仓库**掉出所有榜单后，批量换详情仍能返回该**仓库**及其解读。
9. 未配置 AI 密钥时，采集与页面正常，条目显示英文原始简介与状态角标，不出现半截中文。
10. AI 返回非 JSON 或三段缺一时，重试累计 3 次后标记失败，D1 中不写入不完整解读，管理端点可重跑。
11. 上游桩返回不含 RSC 的空壳时，该榜沿用上一**期次**，响应里带有数据新鲜度状态。
12. 标识非法的条目被丢弃并留下警告，该榜当期条数可少于 25 且没有无效链接。
13. 管理端点无令牌返回 401，带令牌返回 200；首页不存在刷新按钮。
14. 公开读取接口带缓存头；批量换详情走 POST 且不携带任何用户身份。
15. 在 1920×1080 视口下，六张榜单卡片铺满视口、整页无滚动条、卡内可滚动到第 25 条。
16. 卡片显示**简介**；抽屉显示三段解读、英文原文、当期指标、GitHub 外链、复制地址与收藏，且标注「AI 解读」。
17. 收藏写入浏览器本地存储，刷新页面后仍在；掉榜**仓库**仍出现在只看收藏视图。
18. 日期选择只列出已存在的**期次**，界面日期均带 `UTC` 标注。
19. 移动端单列可用；无外部字体请求、无入场动画。
20. 首次部署空状态给出明确说明与手动触发采集的指引。
21. 更换 AI 供应商或模型只需改动部署配置变量/密钥，不改代码、不重新构建前端。
22. 术语表与四条 ADR 中的约束在接口字段、界面文案与测试断言中保持一致。

## Out of Scope（非目标）

- 抓取 GitHub「当日新建仓库」、按创建时间检索或过滤，以及任何非 TrendShift 的数据源。
- 登录、账号、跨设备同步、服务端收藏表、用户画像或任何用户数据的存储。
- 分钟级 / 小时级刷新、实时承诺、当日提及榜的分版本历史；newsnow 只作界面参考。
- 官方 API、无头浏览器、Cloudflare Browser Rendering、Queues、KV、Durable Objects、Rate Limiting、Cloudflare Access、CORS 配置。
- 浏览器直连 AI、访客自带密钥、按需生成解读、离线脚本预生成解读。
- 全局搜索、收藏导出/导入、深浅双主题、频道标签页、评论 / 点赞 / 分享、RSS 或邮件订阅、多语言界面。
- 用 GitHub API 补齐星数、全量抓取 README、翻译整篇 README、从参考 HTML 导入历史中文简介作为 seed。
- 任何写操作对匿名访客开放。

## Further Notes

- 全文用词以根术语表为准；「卡片」在界面语境指 UI 容器，不是**仓库**的别名；不把**期次**称作快照或版本。
- 必须遵守四条 ADR：RSC 载荷解析、UTC 日一期且不实时、服务端预生成解读且密钥不出 Worker、无账号且收藏只存浏览器。
- 实测依据（2026-11-09）：六个榜单页普通 HTTP 请求都含完整 RSC 载荷，每榜 25 条；载荷里只有 `owner/name`，没有现成仓库地址；日/周/月/年榜带 UTC `date`，当日提及榜只有分钟级 `posted_at`。
- 参考实现把 `problem_solved_zh` 排为第三顺位兜底、且从未填过数据在页面几乎看不到 —— 本 spec 不沿用该做法。
- 三段长度、每轮处理数量、重试上限、README 截断长度、收藏上限是可调参数；「三段齐全才算完成」与「一仓库一解读」不是。
- 界面里的增长数存在 `gained > stars` 的情况，属上游双口径正常现象，按原值展示不做修正。
- 本 spec 状态为 `可自动开发`，无需额外 triage 即可由 AFK agent 接手。
