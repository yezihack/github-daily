# 01: 最薄端到端：日榜真实数据上屏

**What to build:** 访客打开页面，能看到当天日榜 25 个真实**仓库**：英文原始简介、星数和可点开的 GitHub 地址。数据从真实 TrendShift 首包 HTML 的 RSC 载荷里来，经最小 D1 与一个只读接口到达页面，运维可手动触发一次采集。此刻没有**中文解读**、没有**收藏**、没有历史回看、没有全屏网格 —— 但采集、存储、接口、界面、测试、部署六层全部真实贯通，不是任何一层的桩。本任务同时立起 Worker HTTP 边界这条唯一的自动化测试缝，后续任务只做增量。

**Blocked by:** None (can start immediately)

**Status:** 可自动开发

- [ ] 手动触发一次采集后，公开只读接口返回日榜 25 条，每条含 rank、stars、forks、gained、语言、标签与英文原始简介
- [ ] 每条都能得出可点击的 GitHub **仓库**地址；地址由归一化标识确定性拼出并只在**仓库**上保存一次
- [ ] 页面渲染该 25 条，仓库名链接在新标签打开
- [ ] 标识不符合 `owner/name` 形态的条目被丢弃并留下警告，该榜条数可少于 25 且没有无效链接
- [ ] 大小写写法不同的同一仓库只占一条**仓库**记录
- [ ] 采集、D1 写入、接口返回跑在真实本地 D1 上；上游 HTML 用固定夹具
- [ ] Worker HTTP 边界的自动化测试通过：断言状态码与响应契约，不 mock D1、不断言内部函数或 SQL 写法
- [ ] 部署骨架可用：D1 绑定、静态资源托管、前端构建产物能由同一个 Worker 提供
- [ ] 字段命名遵循术语表与四条 ADR；D1 中不出现用户表或**收藏**表
