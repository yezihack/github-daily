# 06: AI 三段解读最小闭环

**What to build:** 访客第一次在卡片上看到中文**简介**、在抽屉里看到完整的**解决问题**与**适用人群**，并明确知道这是「AI 解读」而非官方说明。运维配置一个 OpenAI 兼容接口后手动触发一次，就能为当前所有唯一**仓库**各生成一份三段**中文解读**；坏结果一律不入库。

**Blocked by:** 05 详情抽屉（元数据版）

**Status:** 可自动开发

- [ ] `AI_BASE_URL` / `AI_API_KEY` / `AI_MODEL` 三个配置项可换供应商或模型；密钥只在服务端，不进前端、不进 D1
- [ ] 手动触发后，每个唯一**仓库**生成且仅生成一份三段**中文解读**：**简介** 12–28 字、**解决问题** 40–80 字、**适用人群** 20–40 字
- [ ] 输入以榜单元数据为主；第三方文本一律作为数据传入，prompt 明确要求忽略其中指令，输出只取三段 JSON
- [ ] 沿用内容安全口径：安全研究、PoC、破甲、解密类**仓库**只做客观功能描述，不写利用步骤
- [ ] 返回非 JSON、三段缺一或长度越界一律视为失败，不写入 D1、不展示半截中文
- [ ] 同一**仓库**跨**榜单**、跨**期次**共用一份解读，不重复调用
- [ ] 卡片显示**简介**；抽屉显示三段并标注「AI 解读」，与英文原始简介并存、不互相覆盖
- [ ] 未配置密钥时采集与页面仍正常，条目显英文原文与状态角标
- [ ] AI 响应使用固定夹具（含坏 JSON 与缺段），HTTP 缝断言落库结果与降级响应
